# 15: 可复现性能基线与 SLO 冻结

**What to build:** Phase 0 第 4 项。建立合成数据集生成器、基准工具与本机验收脚本，测量冷启动、规则扫描、空间分析、重复哈希、取消延迟与峰值资源；测量结果冻结为 SLO 候选前必须先在文档中定义：设备与 OS build、数据集构成（文件数量与大小分布）、冷/热缓存、计时起止点、p50/p95、峰值内存、CPU 与磁盘读取量。`docs/performance-history-probe.md` 是历史读取的小样本先行探索，可作为方法参考但不得当作基线结论。

**Blocked by:** None。合成数据集只写入系统临时目录下的 GUID 目录；不得对真实用户数据做基准测量。

**Status:** ready-for-agent

- [ ] 合成数据集生成器（可复现：固定种子、固定的文件数量/大小分布、目录深度与重名结构；输出到临时目录）
- [ ] 基准入口（CLI 子命令或独立脚本）：冷启动、规则扫描、空间分析、重复哈希、取消延迟、峰值内存/CPU，逐项可独立运行
- [ ] 本机验收脚本一键跑全套并输出机器可读结果（JSON），含环境信息（设备、OS build、SDK 版本）
- [ ] 每项指标记录计时起止点与冷/热缓存定义；取消延迟按 goals.md 口径（1 秒内显示进度、取消后 2 秒内反馈）
- [ ] 测量结果写入 `docs/performance-baseline.md`（原始数据 + 汇总），与 SLO 候选分开陈述
- [ ] SLO 冻结单独一节：只有可复现数据齐备的指标才标注「已冻结」，其余保持「候选」
- [ ] 文档不宣称未测得的性能；单次机器的测量不得写成全产品承诺

**边界：** 本票只建立基线与候选 SLO；不得为达标而改动功能语义。若测量暴露性能缺陷，另立修复票。
