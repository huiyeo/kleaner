# 14: 操作历史哈希链（篡改可发现）

**What to build:** 依据 ADR-0002 的结论，凭据来源认证在同权限攻击者模型下不可达成；对「强制审计」北极星真正有效的强化是让 `history.jsonl` 本身具备**篡改可发现性**：每条追加记录携带前一条记录内容的哈希，形成可校验的链条。历史窗口展示与 `RecoverPendingAudit` 等读取路径在校验失败时明确提示「历史完整性校验失败」（含首个断裂位置），不得静默跳过或伪装为完整。

**Blocked by:** None（工单 10 已收口；本票是其后续强化）。测试仅使用注入的临时 history 路径，不得触真实历史文件。

**Status:** complete

- [x] `HistoryManager` 追加路径写入链哈希（`prev` 字段，值为前一行原文 SHA-256；旧版无链记录可读并计为未链段）
- [x] `RecentVerified` / 历史窗口展示时校验链条，断裂给出断行位置、检查点不符单独提示，不伪装完整
- [x] 补记路径（`AppendOnce`）在链条断裂或检查点不符时抛 `InvalidDataException`，fail-closed 拒绝追加
- [x] xunit 覆盖：正常链接与检查点更新、删除中间记录、截断尾部、插入伪造记录、旧版未链记录接链、断裂时补记拒绝（`HistoryChainTests`，先失败后通过）
- [x] UI 文案进 `Strings.zh-CN.json`；同步 `docs/deletion-path.md`
- [x] 文档与 UI 措辞不宣称「防篡改」：哈希链是检测不是预防，攻击者理论上可重算整链

**边界（承 ADR-0002）：** 本票不改变「同权限本地进程可伪造一切本机数据」的威胁模型结论；它提高篡改成本并让删改对用户可见。越权级方案（受控签名链、提权服务、TPM 锚定）超出本产品范围。

## Comments

实现要点：`HistoryEntry` 新增可空 `prev` 字段（旧记录反序列化为 null，兼容读取）；追加路径以文件当前最后一行的原文哈希为种子，旧记录同样作为链起点；`<历史文件>.head` 保存最后一条记录的链哈希，检查点写入失败中止审计追加（fail-closed），检查点滞后（崩溃窗口）通过「检查点对应行仍在文件中即视为正常增长」容忍，不产生假警报。链在超长敌意行之后重新起段（原文不可得无法链接）。校验发现的断裂在历史窗口以提示条展示，记录照常列出，不伪装完整。

实施中发现并修复一个潜在防线缺口：测试夹具的规则模式覆盖整个临时目录，把历史文件与检查点一并扫进清理计划移走（旧代码静默容忍、重建空历史继续写）。`Execute` 现在对历史文件与检查点一律跳过并计入 Skipped（`审计文件不可被清理规则扫入隔离区` 回归先失败后通过）——审计本体的不可触碰性是哈希链有意义的前提。

验收：完整测试 167/167、Release 零警告零错误。历史窗口经电脑操作在真实环境验证：现有 6 条旧记录正确显示「包含 6 条启用链保护之前的旧记录」提示条，全程只读（真实历史哈希前后一致）。
