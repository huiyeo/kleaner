# 本地 AI 助手预览：技术选型与威胁模型（Phase 3 前置）

> goals.md Phase 3 要求 AI 预览发布前必须先写 ADR/威胁模型。本 ADR 为 Phase 3 的前置工件：技术选型提议 + 威胁模型 + 故障验收矩阵。**实施阶段需要本机本地模型服务（如 Ollama）到位；文档本身不依赖模型。**

## 决策（提议）

**AI 定位**：可选解释层，不是安全决策层——扫描结果发布后的「帮我看懂这些建议」问答；基础扫描与清理完全不依赖 AI，AI 不可用时产品功能零损失。

**连接形态**：仅本机回环地址上的 OpenAI 兼容 chat API（Ollama `http://127.0.0.1:11434/v1`、LM Studio 同协议）。不内置模型、不自动下载模型（goals.md 宪法）；模型由用户自行安装与管理，Kleaner 不触碰模型供应链。

**启用模型**：默认关闭；用户在设置中显式启用并（可选）修改端点。启用状态与端点持久化于 settings.json。

**发送的数据**（goals.md 边界：AI 只接收分类、脱敏后的结构化元数据，不接收完整路径与身份信息）：分类名、文件数、可释放字节数、规则安全等级——**不含路径、不含文件名、不含用户身份**。

**输出约束**：AI 回复仅作展示文本（长度上限 + 纯文本渲染防注入标记），永不进入清理链路、永不改规则库、永不调用任何工具。

## 威胁模型（STRIDE 摘要）

| 威胁 | 场景 | 缓解 |
|---|---|---|
| 提示注入（T） | 恶意构造的目录/文件名进入扫描数据 → 模型被诱导输出恶意指令 | 输出仅纯文本展示；不执行、不进清理链路；输出长度上限；注入标记检测（如「忽略上述指令」模式降权提示） |
| 误信（R） | 用户把 AI 解释当安全保证 | UI 强免责标注：「AI 解释不构成安全保证，以规则库 safetyNotes 为准」；安全结论只引用规则库 |
| 隐私泄露（I） | 扫描数据发送至本地服务进程 | 仅回环 + 显式启用 + 脱敏元数据（无路径/身份）；默认离线不变 |
| 供应链（T） | 恶意模型文件 | 模型由用户自装自管，Kleaner 不下载不校验不背书——文档声明信任边界 |
| 拒绝服务（D） | 本地服务无响应/超长输出拖垮 UI | 请求超时 + 输出长度上限 + 失败降级为无 AI 模式（主流程零损失） |

## 故障验收矩阵（实施票的验收清单）

| 故障 | 预期 |
|---|---|
| 本地服务未启动/连接拒绝 | 降级提示「AI 服务不可用」，主流程零影响 |
| 请求超时（>30s） | 取消并降级，UI 可取消 |
| HTTP 5xx / 非 JSON / 输出超长 | 降级提示，不渲染原始错误到用户界面（信息泄露面） |
| 模型输出含疑似注入模式 | 降权展示 + 免责标注 |
| 服务中途断开 | 已收到的部分文本丢弃或标注截断 |

## 替代方案

- **不做 AI**：Phase 3 跳过——产品功能零损失（AI 是可选层）。
- **云端 LLM**：违反隐私宪法（默认完全离线、不上传），排除。
- **内置模型**：违反「不内置或自动下载模型」，排除。

## Consequences

- 实施前置条件：本机本地模型服务（Ollama 或兼容 OpenAI chat 的服务）。
- 实施票将新增 `Kleaner.AiAssistant`（或 App 内模块）——依赖方向与工程划分届时在实施 ADR 修订中定。
- 本 ADR 为 proposed：技术选型（端点/协议默认值）待所有者确认后转 accepted。

## 待决输入（所有者）

1. 是否接受「OpenAI 兼容 chat API + 默认 Ollama 端点」的适配器选型。
2. 解释功能的交互形态偏好（扫描结果页内嵌问答 vs 独立对话窗）。
