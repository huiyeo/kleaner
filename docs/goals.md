# Kleaner 长期目标（无人值守推进的北极星）

> 本文档是无人值守会话的行动授权与边界。任何 Agent 在自主推进本项目前必须先读完本文档与 `AGENTS.md`；两者冲突时，以 `AGENTS.md` 的安全条款为最低边界。本目标由 2026-09-05 的需求、功能、性能、安全访谈及独立代码审查共同形成。

## 北极星

将 Kleaner 打造为一款面向非技术普通用户、中文优先的 Windows 安全空间管理工具。

Kleaner 不追求“删得最多”，而要让用户清楚知道：空间被什么占用、哪些内容经过验证可以安全清理、为什么可以清理，以及出现问题后如何完整还原。

可证明的长期承诺：

- 任何可执行清理项都能关联到版本化规则、验证状态和安全依据。
- 任何文件状态变化都有完整、不可静默省略的事务与审计记录。
- 任何未经验证、证据不足或执行时已不满足规则的对象都不可执行。
- 空间诊断可以只读扫描用户明确选择的盘或目录，但诊断结果不自动获得清理资格。

## 目标用户与产品体验

- 第一优先用户是不懂技术、只想安全释放空间的普通 Windows 用户。
- 首页以“安全扫描”为唯一主要动作；结果按“推荐清理 / 建议保留 / 需要了解”分层，规则级细节折叠到“为什么安全”。
- 空间分析、重复文件、启动项、高级模式和未来 AI 助手均为次级入口，不干扰主流程。
- 中文界面在 100%、125%、150% 缩放下文字完整；支持键盘、高对比度、清晰焦点，状态不只依赖颜色表达。
- 开发者自身使用是内部 dogfood 门槛，不改变“普通用户优先”的产品取舍。

## 安全宪法

1. **严格授权**：只有规则引擎基于已验证规则签发的执行计划可进入清理执行器；裸路径、伪规则 ID、AI 建议和只读诊断结果均不可执行。
2. **执行时复验**：真正移动文件前再次校验规则版本、路径、年龄、排除项、reparse point 与文件现状；不满足即跳过并说明。
3. **强制预览与确认**：所有清理必须先展示计划并由用户明确确认；CLI 保持 `--apply` 与非交互 `--yes` 双闸。
4. **事务隔离与可恢复**：清理只能移入隔离区；清单必须可恢复、原子落盘并记录逐项状态。隔离区不可用、审计不可用或事务初始化失败时，拒绝改变文件状态。
5. **强制审计**：清理、还原、手动清空及所有其他文件状态变化都必须落历史；部分成功必须准确记录为 partial，不得伪装为成功。
6. **失败时保留数据**：被占用、无权限、跨卷、空间不足、清单损坏、进程中断或部分还原失败时，优先保留原文件或剩余隔离文件，禁止静默永久删除。
7. **规则可信**：默认推荐至少要求结构化验证状态、低风险和有效证据；缺失字段一律按未验证处理。规则更新只接受官方签名清单，具备抗降级、原子替换和最后已知良好版本回退。
8. **明确不做**：不做注册表清理、驱动更新、内存加速、后台自动清理、系统组件强制删除或绕开隔离区的清理。高风险系统项只读分析或引导至 Windows 官方工具。

用户手动清空隔离区是不可逆操作，必须使用高强度确认并准确审计；不得把这一能力描述为“仓库不存在永久删除”。默认 7 天仅是当前“可清理”提示阈值，不是自动删除期限或不可变产品宪法。

## 隐私与联网

- 默认完全离线，不上传路径、文件名、扫描结果、诊断信息或 AI 会话。
- 用户主动检查更新时，应用仅连接项目官方更新源并验证签名、版本与完整性。
- 性能或故障诊断只通过用户主动导出的脱敏报告进行；报告不含原始路径和文件名。

## 性能目标

以下数字是待基准工程验证后冻结的候选 SLO，不得在没有可复现数据集和测量方法时宣称已经达标。

基准设备：Windows 11 x64、4 核 CPU、8 GB 内存、SATA SSD。Windows 10 22H2 x64 仅作为 best-effort 兼容性目标，不作为持续安全支持承诺。

- 冷启动候选目标：p95 小于 2 秒。
- 典型规则安全扫描候选目标：p95 小于 15 秒。
- 重型扫描不承诺固定完成时间，但应在 1 秒内显示进度；取消后 2 秒内反馈正在停止或已经停止。
- 同一磁盘同时只运行一个重型遍历任务；默认限制 CPU、磁盘和内存，电池供电或磁盘繁忙时主动降速。
- 遍历与结果采用流式、有界处理；Top-K、重复文件分组、哈希、界面节点和日志均有明确上限与截断提示。
- 不持久化完整文件索引；会话内可复用脱敏元数据，但执行前必须重新校验。
- 已取消或不完整的扫描结果不得成为可执行清理计划。

每项冻结 SLO 前必须定义：设备、OS build、合成/真实数据集、文件数量和大小分布、冷/热缓存、计时起止点、p50/p95、峰值内存、CPU 与磁盘读取量。

## AI 长期边界

AI 是可选解释层，不是安全决策层；基础扫描和清理完全不依赖 AI。

- 正式版只连接本机回环地址上的本地模型服务，不内置或自动下载模型，不允许远程端点。
- “回环地址”只减少数据离机风险，不代表第三方本地模型服务天然可信；界面必须明确这一独立信任边界。
- AI 只接收分类、脱敏后的结构化元数据，不接收文件或缓存正文、完整路径和身份信息。
- 模型没有文件、网络、命令和清理工具调用权限；输出只作解释、问答和不可执行的审阅计划。
- 回答必须关联规则名称、版本、安全说明和适用边界；证据不足时明确回答“不确定”。
- 会话默认只存在于内存中；仅允许用户主动导出脱敏报告。
- AI 研究实验室只生成候选规则报告；候选必须补齐权威来源、安全边界、真机验证与自动化测试，才能进入正式规则库。
- AI 预览发布前必须另写 ADR/威胁模型，并以假模型、恶意输入和故障场景证明它无法越过确定性规则链路。

## 阶段目标（严格按序）

### Phase 0（✅ 2026-09-08 完成）：证明安全宪法不可绕过

Phase 0 完成前冻结新功能、规则扩量和 AI 实现。按工单逐项完成：

1. 收紧执行授权：工具箱大文件/重复文件保持只读；执行器只接受规则引擎签发的计划，拒绝裸路径和伪规则 ID。
2. 强制审计和事务隔离：审计不可缺失；修复部分还原、唯一批次 ID、预写/原子 manifest、逐项状态、异常恢复和执行时复验。
3. 建立规则与更新信任：运行时完整校验 Schema，验证状态 fail-closed；官方签名、抗降级、原子更新和最后已知良好版本。
4. 建立可复现性能基线：合成数据集、基准工具和本机验收脚本；测量启动、规则扫描、空间分析、重复哈希、取消延迟和峰值资源，再冻结 SLO。
5. 统一权威文档与发布门禁：修正 README、architecture、context、deletion-path、publish 与实际代码的冲突；补安装/升级/回退/卸载矩阵、产物校验和依赖治理。

Phase 0 发布阻断指标：**零未授权清理、零未审计文件状态变化、部分失败零数据丢失**。

## 自主推进规则

1. **一次只做一张工单**：大目标先拆票；构建、测试和该工单专属验收全绿，按 `docs/conventions.md` 提交后，才开始下一张。
2. **卡点即停**：需求歧义、安全边界冲突或需要真实机器执行删除时，将工单标记为 `blocked`，写明证据与所需输入；不得以免责声明、专家模式或用户自担风险绕过。
3. **测试隔离**：自动化测试只能使用注入的临时目录、假注册表、假启动目录、假更新源和假模型；不得在真实系统执行清理、注册表写入或启动项修改。
4. **证据优先**：构建成功不等于运行时、视觉、性能或安全验收成功；每项声明必须有与其范围相匹配的证据。
5. **文档同步**：改变安全、执行、规则、更新、发布或 AI 边界时，同一工单同步修改相应权威文档。
6. **Git 安全**：只允许快进推送；永不改写远程历史，永不 force。推送失败最多重试两次并记录。

## 完成定义

长期北极星没有一次性终点；每个 Phase 必须用可验证工件收口。Phase 或工单只有在以下条件同时成立时才算完成：

- 范围内的代码、测试、文档和用户界面一致。
- 自动化测试覆盖成功、失败、取消、部分成功、损坏输入和恢复路径。
- 所有安全不变量都有能够先失败、修复后通过的回归测试。
- 性能结论来自固定环境和可复现数据，而不是开发机主观感受。
- 真机、视觉或发布要求有对应验收记录，不能由编译通过代替。
