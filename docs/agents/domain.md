# 领域文档

工程技能探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- **`docs/context.md`**：Kleaner 术语表，领域词汇唯一出处。规则 / 执行 / 产品三个域的词义与歧义都在这里。
- **`docs/adr/`**：触及即将动工的领域时读相关 ADR。

以上文件不存在时**静默继续**。不要标记缺失、不要主动建议创建。`/domain-modeling` 技能（经 `/grill-with-docs`、`/improve-codebase-architecture` 触达）在术语或决策真正落定时才惰性创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── docs/context.md        ← 术语表（领域词汇）
├── docs/adr/              ← 决策记录（当前不存在，按需创建）
├── docs/architecture.md   ← 工程结构
├── docs/rules.md          ← 规则库契约
├── rules/                 ← 规则库本体
└── src/
```

## 使用术语表的词汇

输出命名领域概念（工单标题、重构提案、假设、测试名）时，用 `docs/context.md` 中的定义词。不要漂移到术语表明确回避的同义词。

需要的概念不在术语表里，是个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记给 `/domain-modeling`）。

## 标注 ADR 冲突

输出与既有 ADR 矛盾时，显式提出而非静默覆盖：

> _与 ADR-XXXX 冲突，但值得重开，因为……_
