# 历史读取成本探针

工单 10 的局部证据，不是 Phase 0 的完整性能基线或 SLO 验收。

## 方法

- 测试：`HistoryReadBenchmarkTests`，只在 GUID 临时目录生成并读取日志。
- 夹具：5000 条、1228890 字节，每条 Detail 为 128 个 ASCII 字符；时间戳按序号模 137 分布，故意乱序且存在同时间记录。
- 对照：旧整文件读取/排序与当前流式 Top-K；先验证完整返回结果一致，再各运行 5 次热读。
- 环境：当前 Windows 开发机，x64 .NET 10.0.11，Release；未固定 CPU 频率、磁盘缓存、后台负载和目标验收设备。
- 计时：从调用读取方法到返回列表。分配量：当前线程累计分配字节差，不是峰值堆、驻留内存或磁盘读取量。夹具生成与结果断言不计时。

复现：

```powershell
dotnet test tests/Kleaner.Core.Tests/Kleaner.Core.Tests.csproj -c Release --filter FullyQualifiedName~HistoryReadBenchmarkTests --logger 'console;verbosity=detailed'
```

## 本轮最终实现样本

| 方法 | 热读中位数 | 最大值 | 平均分配字节 |
|---|---:|---:|---:|
| 旧整文件读取/排序 | 38.74 ms | 44.43 ms | 5801094 |
| 分块读取/Top-K | 27.67 ms | 33.32 ms | 5570214 |

调试期间逐字符版本曾慢于旧实现（51.46 ms 对 29.85 ms）；改为分块查换行，并只在候选进入 Top-K 时更新堆后复测如上。样本少、运行顺序固定且环境未隔离，不能据此承诺普遍提速，也不能把最大值称为 p95。

## 已证明与未证明

- 结果与旧排序一致，包括同时间戳顺序；保留集合最多 K 项，K 上限 1000。
- 单行读取最多保留 65536 字符；审计读取无限无换行输入时，在读取不超过 69632 字符后拒绝。展示可跳过超长行，不删除日志内容。
- 尚未证明：完整设备矩阵、冷启动、端到端还原 p95、峰值资源、UI 响应性、取消延迟。
- 尚未优化：`AppendOnce` 对每个还原文件重新扫描完整日志的 IO 成本。此问题仍属工单 10，不因读取边界修复而关闭。
