# 规则治理指标（Phase 2 / 工单 rule-governance 01）

goals.md Phase 2 要求「目标从规则数量改为目标软件覆盖率、证据覆盖率、验证覆盖率、推荐准确率和误伤事件数」。本文件给出**可测量口径**与基线。测量工具：`Kleaner.ScanCli governance-report`（纯规则库只读测量，不扫描文件系统、不写状态）。

## 可测量口径

| 指标 | 口径 | 数据源 | 状态 |
|---|---|---|---|

| 软件覆盖率（目标根） | 规则 `paths` 开头的唯一目标根数（`%环境变量%` 或盘符，大小写不敏感去重；**不展开实际路径**——保证指标跨机器确定性） | rules.v1.json | ✅ 已实现 |

## 基线（rules.v1.json @ main）

2026-09-10 首跑：

```
规则总数               101
证据覆盖率            100.0%  （101/101）
验证覆盖率             23.8%  （24/101）
默认勾选规则数          24
分类覆盖              6 / 6
唯一目标根               5   （%TEMP% %LOCALAPPDATA% %WINDIR% 等环境变量根）
```

2026-09-11 追加维护标注（工单 rule-governance 06 回填，基线=当日治理基线审计）：维护责任标注 101/101、证据超龄 0。

解读：证据覆盖率满分（Phase 0 工单 11 的成果：所有规则都有安全性说明与文档锚点）；验证覆盖率 23.8% 与「只有本机实测的 24 条默认勾选」的产品语义一致——**验证覆盖率低不是缺陷而是保守策略的体现**，提升它的途径是真机实测更多规则而非放松口径。

## 目标值与阈值

**已确认（2026-09-10，用户）**：目标值框架 `GovernanceTarget.Phase2Initial`——证据覆盖率 1.0 保持、验证覆盖率阶段一 ≥0.25、分类 6/6。低于阈值仅**警告不阻塞构建**（治理指标非安全不变量）。冻结 SLO 的经验（先基线后冻结、范围限定显式声明）同样适用于治理指标的后续收紧。另有两条警告：维护标注缺失、证据超龄（>180 天）。

## 已知局限

- 「推荐准确率」无法离线计算：需要用户侧勾选/跳过行为的遥测数据，而 goals.md 隐私边界禁止默认遥测。任何准确率数字必须来自显式 opted-in 的数据源。
- 误伤信号是代理信号（还原≠确认误伤），仅供人工复核与趋势观察。
- 目标根计数不含真实路径展开——同一环境变量在不同机器指向不同目录，指标因此跨机器稳定但精度有限。
- 维护标注仅治理可见性：不参与扫描/清理决策，签名渠道（rules-channel）的 manifest 重发布尚未随字段回填执行（待下次规则更新窗口）。
