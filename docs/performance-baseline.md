# 性能基线与 SLO（工单 15）

本文件记录可复现的性能测量结果与已冻结的 SLO。现行 SLO 由 **2026-09-11 重新冻结**（见文末对应节）：其 rules-scan / cancel 场景口径已修正为合成数据集作用域，此前的 rules-scan / cancel 记录实为真机口径（口径异常的定位与修正见「内存口径异常与测量口径修正」节）。范围限定与遗留缺口随表陈述，对外引用时必须连同限定一起。

## 复现方式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/bench.ps1 -Files 2000 -Iterations 5 -ColdStarts 5
```

脚本依次执行：Release 构建 → `gen-dataset` 生成合成数据集并在数据集根写出 `bench-rules.json`（数据集作用域的基准规则夹具，`SyntheticBenchRules`）→ `bench` 携带 `--rules` 做五场景测量（每场景独立子进程，采集峰值工作集、CPU 时间与磁盘读写字节）→ 冷启动 5 次（进程启动到主窗口句柄出现）→ 汇总写入 `docs/performance/performance-run-<时间戳>.json`。结果 JSON 自带 `rulesPath` 字段：缺失表示该次运行的 rules-scan / cancel 回退到了捆绑真实规则库（真机口径，跨日不可比）。

## 测量口径

| 项目 | 计时起止点 | 缓存定义 |
|---|---|---|
| rules-scan | `ScanEngine.Scan` 单次完整调用（含规则加载与逐规则枚举），Stopwatch 覆盖 | 热缓存（数据集刚生成、前一迭代已读入） |
| usage | `DiskUsageAnalyzer.TopLevel` 完整枚举 | 热缓存 |
| large-files | `LargeFileScanner.Scan`（阈值 64KB，top 100） | 热缓存 |
| duplicates | `DuplicateFinder.Find`（阈值 64B） | 热缓存 |
| cancel | 首个进度回调时延（扫描开始 → 首个 `ScanProgress`）；取消时延（`Cancel()` → `Scan` 返回，含 `OperationCanceledException` 结束） | 热缓存 |
| 冷启动 | `Process.Start` → 主窗口句柄首次非零 | 首次为冷文件缓存，其余为热缓存（脚本顺序执行） |

rules-scan 与 cancel 的规则集为 `bench-rules.json`（5 条规则 / 8 个模式，覆盖 GlobScanner 的精确路径、末段通配、中间通配+递归、`**` 递归、exclude 整路径排除与 keepNewest 分支）；2026-09-11 口径修正之前，这两个场景回退捆绑真实规则库（101 条 / 906 模式）扫描真实用户目录——历史数据见下文各节，已重新标注。

百分位取最近邻秩（升序第 ⌈p/100·n⌉ 个）。峰值内存与磁盘读写字节均为子进程自报的 `PeakWorkingSet64` 与进程 IO 计数器。

- 2000 个文件，共 595.6 MB；目录树 3 层 × 每层 4 分支（84 个目录）

## 内存口径异常与测量口径修正（2026-09-11 定位）

### 异常与定位过程

09-08 冻结时 rules-scan 峰值内存 59.8MB，09-11 同参数复跑 285.7MB（旧实现受控对照 252.6MB / 新实现 295.2MB），差异来源当天未定。当晚按下述证据链定位，结论是**测量口径错误，不是内存回归**：

1. **代码事实**：`Benchmarks.RunOnce` 的 rules-scan / cancel 场景写作 `new ScanEngine(root).Scan(set)`，而 `ScanEngine` 构造参数是**隔离区排除根**，不是扫描根；真正的扫描路径来自 `RuleSetLoader` 加载的规则文件。bench 调用链未传 `--rules`，于是回退捆绑真实规则库（101 条 / 906 模式）**未提权扫描真实用户目录**；传入的合成数据集根只起排除作用（防止 user-temp 类规则把数据集本身扫进结果）。本文件 2026-09-06 起对 rules-scan 的「合成数据集口径」标注自始不成立；usage / large-files / duplicates / 冷启动不受影响（它们确实以数据集为对象）。
2. **差分证据**：09-08 → 09-11 期间，cancel（加载同一规则库、首个规则后取消）峰值内存稳定（62.2 → 61.3MB），usage / large-files / duplicates 稳定（32.7/35.4/47.7 → 37.4/40.1/49.7MB），唯独 rules-scan 漂移（59.8 → 285.7MB）——漂移被限定在「完整逐规则枚举真实目录」路径内，排除运行时/GC 配置与规则库内容变化（两天规则库均为 101 条 / 906 模式，SDK 均为 10.0.400）。
3. **受控复现（09-11 晚，三次探针）**：

| 探针 | 引擎 | 对象 | 耗时 | 峰值内存 |
|---|---|---|---|---|
| P1 | 新（单趟枚举） | 真实用户目录（bench-single rules-scan，未提权） | 1.5–3.1 s | 288.7 MB |
| P2 | 新 | 真实用户目录（CLI `scan`，未提权） | ~1.4 s | —（3275 文件 / 611.5 MB，10 条规则命中：dev-nuget-cache 371.3MB、windows-update-download 823 文件、chrome-http-cache 810 文件等） |
| P3 | 旧（优化前，worktree 检出 cab6128^） | 真实用户目录（bench-single rules-scan，未提权，5 轮） | 89–116 s | 245.1 MB |

P3 与 09-11 下午的受控对照（旧实现 252.6MB）及真机 CLI 实测（97.6s）互相印证；而 09-08 同代码记录为 59.8MB / 2.7s。代码、规则库、SDK 两天完全一致，唯一变量是被扫描的真实文件系统内容——09-08 与 09-11 之间真实临时/缓存目录显著增长（对照 P2：NuGet 全局缓存损坏 09-10 修复后重建、Windows 更新下载残留、浏览器缓存增长），两次记录各自反映当时的机器状态，**相互不可比**。

4. **结论**：引擎改动本身在真机负载上仅引入 ~+40MB 瞬时分配（GC 滞后垃圾，非存活内存）；「异常」是 rules-scan / cancel 场景的真机依赖口径造成的跨日不可比。

### 修正内容（bench 口径修复）

- `gen-dataset` 生成数据集时同时在数据集根写出 `bench-rules.json`（`SyntheticBenchRules`，5 条规则 / 8 模式，覆盖 GlobScanner 全部分支：精确路径、末段通配、中间通配+递归、`**` 递归、exclude 整路径排除、keepNewest）；仅作测量夹具，不代表真实规则。
- `bench` / `bench-single` 链路透传 `--rules`；`Benchmarks.RunOnce` 在提供 `--rules` 时不再把数据集根当隔离区排除根（否则数据集候选全被排除），回退捆绑真实规则库时保留旧语义。
- `scripts/bench.ps1` 传 `--rules`；结果 JSON 新增 `rulesPath` 字段自描述口径（缺失即真机口径回退，跨日不可比）。
- 回归测试 3 项（规则文件可加载可校验、数据集扫描产出候选且 exclude 生效、深度 1 退化参数仍有效）。

### 冻结条件核销（2026-09-11）

1. ✅ 基线定义齐备：设备、OS build、数据集构成、**规则集构成（本次新增为口径的一部分）**、冷/热缓存、计时起止点、p50/p95、峰值内存、CPU 与磁盘读取量。
2. ✅ 两次相互独立的同参数复跑（同日两个独立进程与数据集），时延 p95 偏差 ≤6%（rules-scan p50 的 +34% 为毫秒级小值噪声，p95 无漂移），内存偏差 ≤0.4%，无正向漂移。
3. ⚠️ 以范围限定替代：SLO 仅对测量机有效；非开发机复测列入后续发布验收。
4. ⚠️ 以范围限定替代：rules-scan 的「典型」口径 = 合成数据集夹具；**真实规则库（906 模式）在真实目录上的成本不再由 bench 跟踪**，其量级参考「真机口径与扫描引擎优化」节的真机数据点（优化后引擎约 2.5 s / 3275 文件 / 611.5 MB，未提权，随机器状态漂移），该口径不可冻结。

## 已知局限

- cancel 场景的首进度时延取决于夹具规则首条（bench-recursive 全树递归）在数据集上的命中节奏；夹具变化会让数字漂移。
- 冷启动样本仅 5 个且首次含文件缓存冷态，p95 统计意义有限；首启值在 1.15–1.99 s 间随测量时缓存状态波动。
- 未测量 UI 端到端呈现时延与省电/降速行为（磁盘读写字节自 09-08 起由进程 IO 计数器采集）。
- rules-scan / cancel 已锚定合成数据集夹具，**不再跟踪真实规则库（906 模式）的规模增长**：真实库成本以「真机口径」节数据点作背景（随机器状态漂移，不可冻结），规则扩张工单（K1/K2 等）验收时需自行附真机量级参考。
- 真实规则库全量扫描（真机、未提权）峰值工作集约 245–295MB，超出 200MB 内存 SLO——该 SLO 的范围是合成数据集场景；真实库工作集水位（含单趟枚举 ~+40MB 瞬时分配）是否需要优化，待真实使用中成为问题时另行立票。
- 单机数据不支持「全产品性能承诺」；任何对外表述必须引用冻结后的 SLO 并连同范围限定。
