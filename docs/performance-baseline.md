# 性能基线与 SLO（工单 15）

本文件记录可复现的性能测量结果与已冻结的 SLO。2026-09-08 起，文末 SLO 表在**测量机与合成数据集范围内**冻结；范围限定与遗留缺口随表陈述，对外引用时必须连同限定一起。

## 复现方式

```powershell
pwsh ./scripts/bench.ps1 -Files 2000 -Iterations 5 -ColdStarts 5
```

脚本依次执行：Release 构建 → `gen-dataset` 生成合成数据集 → `bench` 五场景测量（每场景独立子进程，采集峰值工作集、CPU 时间与磁盘读写字节）→ 冷启动 5 次（进程启动到主窗口句柄出现）→ 汇总写入 `docs/performance/performance-run-<时间戳>.json`。

## 测量口径

| 项目 | 计时起止点 | 缓存定义 |
|---|---|---|
| rules-scan | `ScanEngine.Scan` 单次完整调用（含规则加载与逐规则枚举），Stopwatch 覆盖 | 热缓存（数据集刚生成、前一迭代已读入） |
| usage | `DiskUsageAnalyzer.TopLevel` 完整枚举 | 热缓存 |
| large-files | `LargeFileScanner.Scan`（阈值 64KB，top 100） | 热缓存 |
| duplicates | `DuplicateFinder.Find`（阈值 64B） | 热缓存 |
| cancel | 首个进度回调时延（扫描开始 → 首个 `ScanProgress`）；取消时延（`Cancel()` → `Scan` 返回，含 `OperationCanceledException` 结束） | 热缓存 |
| 冷启动 | `Process.Start` → 主窗口句柄首次非零 | 首次为冷文件缓存，其余为热缓存（脚本顺序执行） |

百分位取最近邻秩（升序第 ⌈p/100·n⌉ 个）。峰值内存与磁盘读写字节均为子进程自报的 `PeakWorkingSet64` 与进程 IO 计数器。

## 本机数据集定义

参数（`gen-dataset --seed 20260906 --files 2000 --depth 3 --branching 4 --dup-groups 20`）：

- 2000 个文件，共 595.6 MB；目录树 3 层 × 每层 4 分支（84 个目录）
- 大小分布：70% 小（64B–16KB）、25% 中（16KB–128KB）、5% 大（128KB–512KB）
- 20 组重复文件（每组 3 副本，逐字节相同），内容随机填充
- 生成写入系统临时目录的 GUID 目录，测后清理；同种子同参数逐字节可复现

## SLO（2026-09-08 冻结，仅对测量机有效）

冻结依据：基线定义齐备（含磁盘读取量）、两次同参数跨日运行落在 ±24% 内且无正向漂移趋势。**范围限定：以下数字仅对本文件记录的测量机（Windows 11 build 26100 / i5-12500H / SDK 10.0.400）与合成数据集（2000 文件 / 595.6 MB / 种子 20260906）有效，不构成对任何其他硬件或真实用户目录的承诺。** 典型用户目录的数据集构成确认与非开发机复测仍待后续发布验收补充；届时如有偏差按本文件流程修订。

## 冻结条件核销（2026-09-08）

1. ✅ 基线定义齐备：设备、OS build、数据集构成、冷/热缓存、计时起止点、p50/p95、峰值内存、CPU 与磁盘读取量（09-08 起脚本新增 IO 计数器采集）。
2. ✅ 两次相互独立的同参数复跑（2026-09-06 与 2026-09-08），p50 偏差 −24%～+2%，无正向漂移。
3. ⚠️ 以范围限定替代：SLO 明确声明仅对测量机有效；非开发机复测列入后续发布验收。
4. ⚠️ 以范围限定替代：「典型规则安全扫描」的口径=本合成数据集并在 SLO 表中显式声明；真实用户目录的分布确认列入后续发布验收。

条件 3、4 的遗留不影响「测量机范围内 SLO 已冻结」的结论，但对外引用本表时**必须**连同范围限定一起陈述。

## 已知局限

- 取消场景的首进度时延依赖真实规则集在合成数据上的命中节奏；规则库变化会让数字漂移。
- 冷启动样本仅 3–5 个且首次含文件缓存冷态，p95 统计意义有限。
- 未测量磁盘读取量、UI 端到端呈现时延与省电/降速行为。
- 单机数据不支持「全产品性能承诺」；任何对外表述必须引用冻结后的 SLO。
